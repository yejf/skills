# 技术文章模板

## 分类特征

技术文章通常包含：代码块、技术术语、API 名称、架构描述、版本号。

## 输出模板结构

```markdown

**技术栈**：[语言/框架/工具]
**版本**：[如有提及]
**适用场景**：[文章中描述的使用场景]

## 核心技术点

### 1. [技术点名称]
- 问题：[解决什么问题]
- 方案：[如何解决]
- 关键代码/配置：

```代码
[保留关键代码片段]
```

### 2. [技术点名称]
...

[描述架构图或设计模式]

- [优势2]

**局限**：

- [场景2]

[如有提及，列出对比方案]

> 「技术相关的精炼表达」
> —— 原文位置：文章第X部分

## 标签

[技术栈] [领域] [关键词]
```

## 提炼规则

### 必须提取
- 技术栈名称和版本
- 解决的核心问题
- 关键代码示例（保留原格式）
- 性能数据（如有）
- 适用场景和限制条件

### 可以忽略
- 技术背景铺垫（除非必要）
- 安装步骤细节（除非是核心）
- 常见问题排查（除非有独特见解）

### 金句选择
优先选择：
- 对技术方案的精炼评价
- 设计哲学的表达
- 经验总结和最佳实践
- 反直觉的技术结论

## 质量检查

- [ ] 技术栈和版本是否标注？
- [ ] 关键代码是否保留原格式？
- [ ] 适用场景是否明确？
- [ ] 优劣分析是否平衡？
