# 内容分类规则

## 分类流程

```
1. 扫描全文，提取特征信号
2. 按优先级匹配分类
3. 如果多个分类匹配，选择信号最强的
4. 如果无明确匹配，使用 general
```

## 8 种分类及判断规则

### 1. tech-article（技术文章）

**强信号**（命中 2 个即判定）：
- 包含代码块（```语言标记）
- 标题或正文出现具体技术名词（框架名、库名、协议名）
- 包含 API 名称或函数名
- 讨论架构、设计模式、性能优化
- 包含版本号（如 v2.0、React 18）

**弱信号**（辅助判断）：
- 作者自述为开发者/工程师
- 发布在技术博客平台（Medium 技术板块、Dev.to、掘金、思否）
- 包含技术标签（#javascript、#python）

**典型来源**：
- 个人技术博客
- 技术媒体（InfoQ、CSDN、掘金）
- 官方文档/博客
- GitHub 上的文章

### 2. tutorial（教程）

**强信号**（命中 2 个即判定）：
- 标题包含 "How to"、"Guide"、"Tutorial"、"教程"、"指南"、"入门"、"实战"
- 正文为步骤式结构（Step 1、Step 2 或编号列表）
- 包含"前置条件"、"准备工作"、"Prerequisites"
- 包含"安装"、"配置"、"运行"等操作动词
- 有明确的"最终效果"或"完成后的结果"

**弱信号**（辅助判断）：
- 文章较长（>2000 字）
- 包含多个代码块且有顺序关系
- 包含截图说明

**典型来源**：
- 技术博客的教程文章
- 官方文档的 Getting Started
- 在线课程的文字版

### 3. news（新闻资讯）

**强信号**（命中 2 个即判定）：
- 包含明确的时间点（今天、昨日、X月X日）
- 报道具体事件（发布、收购、融资、事故）
- 标题包含公司名/产品名 + 动词
- 包含"宣布"、"发布"、"推出"、"收购"等事件动词
- 引用消息来源（据XX报道、知情人士透露）

**弱信号**（辅助判断）：
- 发布在新闻媒体（36氪、TechCrunch、The Verge）
- 文章较短（<1500 字）
- 包含多个超链接引用

**典型来源**：
- 科技媒体新闻稿
- 公司官方公告
- 行业资讯站

### 4. opinion（观点评论）

**强信号**（命中 2 个即判定）：
- 第一人称叙述（"我认为"、"我觉得"、"In my opinion"）
- 明确的立场表达（支持/反对/质疑）
- 包含论证结构（论点→论据→结论）
- 标题为疑问句或判断句（"为什么X是错的"、"X才是未来"）
- 包含"但是"、"然而"、"相反"等转折词密集出现

**弱信号**（辅助判断）：
- 作者有明确的个人立场
- 文章引发争议（评论区有激烈讨论）
- 发布在个人博客或观点专栏

**典型来源**：
- 个人博客思考文
- 专栏评论文章
- 行业观察/分析

### 5. research（研究论文）

**强信号**（命中 2 个即判定）：
- 包含摘要（Abstract）
- 包含方法论描述（Methodology、Methods）
- 包含数据图表（Figure、Table）
- 引用密集（[1]、[2] 或 (Author, Year) 格式）
- 包含"研究发现"、"实验结果"、"数据分析"

**弱信号**（辅助判断）：
- 发布在学术期刊或 arXiv
- 作者有学术机构背景
- 包含参考文献列表

**典型来源**：
- 学术论文
- 研究报告
- 行业白皮书

### 6. paper（学术论文）

**强信号**（命中 2 个即判定）：
- 包含作者机构信息（大学、研究所）
- 包含摘要(Abstract)和关键词(Keywords)
- 有明确的章节结构（Introduction, Methods, Results, Discussion）
- 包含参考文献列表（References）
- 发表在期刊或会议（IEEE, ACM, arXiv, Springer）

**弱信号**（辅助判断）：
- 包含 DOI 编号
- 有基金资助信息
- 包含致谢(Acknowledgments)部分

**典型来源**：
- 学术期刊论文
- 会议论文
- arXiv 预印本
- 学位论文

**与 research 的区别**：
- `research`：行业报告、白皮书、基准测试
- `paper`：正式发表的学术论文

### 7. documentation（官方文档）

**强信号**（命中 2 个即判定）：
- 包含 API 参考（函数签名、参数说明）
- 包含配置项说明（配置键、类型、默认值）
- 有版本信息（v1.0、Since 2.0）
- 包含代码示例（Usage、Example）
- 发布在官方文档站（docs.xxx.com、xxx.readthedocs.io）

**弱信号**（辅助判断）：
- 包含"Deprecated"、"Since"等版本标记
- 有目录结构（Table of Contents）
- 包含"See also"、"Related"等交叉引用

**典型来源**：
- 框架/库官方文档
- API 文档
- SDK 参考手册
- 配置文件说明

**与 tutorial 的区别**：
- `tutorial`：面向任务的分步指南
- `documentation`：面向参考的 API/配置文档

### 8. general（通用）

**适用条件**：以上 7 种都不匹配时使用

**典型场景**：
- 散文、随笔
- 故事、叙事
- 产品介绍（非新闻）
- 列表文章（"10个最佳XX"）
- 个人经历分享

## 分类优先级

当多个分类同时匹配时，按以下优先级选择：

```
tutorial > documentation > tech-article > paper > research > news > opinion > general
```

理由：
- tutorial 的特征最明确（步骤式结构）
- documentation 有明确的 API/配置格式
- tech-article 次之（代码块+技术名词）
- paper 有严格的学术格式
- research 有数据和方法论
- news 有时间敏感性
- opinion 较为主观

## 边界案例处理

**技术教程**：既有代码又有步骤 → `tutorial`（教程优先）
**API 文档教程**：既有 API 参考又有使用指南 → `documentation`（参考优先）
**技术新闻**：报道技术产品发布 → `news`（事件优先）
**技术观点**：对技术方案的评价 → `opinion`（立场优先）
**研究解读**：解读论文的博客文章 → `tech-article`（非原始研究）
**学术论文**：正式发表的研究论文 → `paper`（学术优先）

## 分类结果格式

```json
{
  "category": "tech-article",
  "confidence": "high|medium|low",
  "signals": ["包含代码块", "讨论 React 架构"],
  "fallback": "general"
}
```

- `confidence`：high（3+ 强信号）、medium（2 强信号）、low（1 强信号或仅弱信号）
- `signals`：命中的特征列表
- `fallback`：如果后续提炼失败，降级使用的类型
